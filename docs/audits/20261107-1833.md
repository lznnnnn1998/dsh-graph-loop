## 4. New / remaining findings

### P0-1 — Graph node directives are logged as user messages (blocks UI/session compatibility)

Evidence:

- `packages/loop/src/loop/agent.ts:431-440` builds the node steering text as
  `createUserMessage({ source: { kind: 'user' } })`.
- `packages/loop/src/loop/agent.ts:767-775` appends every non-`runtime-context` admitted message as
  `user/message` to the session log.
- `scripts/e2e-installed.sh:41-42` counts exactly those messages in `session.jsonl`; the rerun
  showed `graph_node_messages=4` for a 4-step turn. `packages/loop/README.md:50` admits the node is a
  “logged user message”.
- Consequence in DSH: `packages/core/session/src/surface.ts:132-136` (read-only DSH checkout) turns every
  `user/message` into model history; the Web API’s `latestUserQuestion` selects the last user-role
  message with `source.kind === 'user'`
  (`/Users/zhinan/deepseek-harness/packages/web/web-deepseek-api/src/index.ts:64`), so a synthetic
  `[graph node ...]` directive can become the “latest human prompt”. The stock session surface treats
  these as user turns, so the synthetic text is part of chat history/model trajectory, and every
  later turn replays it.
- Impact: user-visible noise, inflated prompt bytes, wrong API prompt/search query, and a violated
  “stock loop UI compatibility” contract. Not a compile/runtime blocker, but a blocker to calling B
  complete or shipping it as a drop-in loop.

Suggested fix (scoped): stop creating a user-role message for the node directive. Use the existing
`runtime-context` replacement mechanism (`packages/loop/src/loop/runtime-context.ts`) or a merge-
extended `graph-node` source with a replacement surface op, so at most one live directive exists and
`latestUserQuestion` ignores it. Update `scripts/e2e-installed.sh`, `e2e-headless.sh`,
`e2e-tarball.sh`, `e2e-propose.sh`, `e2e-replan.sh` and `scripts/ab-structural.sh`/`e2e-cross-loop.sh`
to assert the new non-user event/context rather than grepping `[graph node]` in `session.jsonl`.
Add a unit test that no graph directive is a `user/message` with `source.kind === 'user'`.

### P1-1 — Durable graph checkpoints / node trail

`PlanCheckpointer` is a cache interface (`packages/loop/src/kernel/plan.ts:102-105`) with only the
in-memory implementation (`:153-175`); `resolveKernelDeps` defaults to it (`:184`). The LangGraph
compile has no saver (`packages/loop/src/kernel/langgraph.ts:744`), so a restart cannot resume a
turn and the Graph tab cannot replay checkpoint history. `docs/STATUS.md:57-58` covers this, and
`docs/MERGE-LANGGRAPH.md:162-163` marks M3 pending. Deletion of `core/src/checkpoint.ts` is
acceptable (zero importers, no storage wiring), but the capability remains missing.

Scoped next step: implement either a `storageDomain`-backed `PlanCheckpointer` or a LangGraph
`BaseCheckpointSaver`; write at node boundaries, strip `__pregel_*`, reject non-JSON, and expose
`getState`/history to the Graph tab. Keep the session log authoritative; do not add a second
conversation log. Add a restart/resume unit test with a fake storage domain.

### P1-2 — `stepFailedTool` hardcodes `bash`/`pwsh`

`packages/loop/src/loop/agent.ts:592` only records a failed tool name for `bash`/`pwsh`; `:666`
uses it to fail a node when the step produced no tool call; `:671-674` forwards it as
`failedTool`, which selects `callFailed` recovery edges. This is unguarded by `benchGuards` and
tool-specific, contradicting the tool-agnostic rule that the same commit claims to enforce
elsewhere. A failure of another tool with a subsequent successful tool is treated differently from
a shell failure.

Scoped fix: track the first errored tool generically (or derive node failure from “step did not
complete / every tool failed” only), keep the shell special case behind `benchGuards` if it is
needed for Terminal-Bench, and add a unit test for a non-shell failed tool with a `callFailed` edge.

### P1-3 — Typed channels and LangGraph parallel execution are still future work

The live graph state is one JSON object; the LangGraph root uses replace reducers over the same
fields (`packages/loop/src/kernel/langgraph.ts:722-724`). Fan-out/join, subagent batches and
non-`callFailed` conditions remain on `FrontierTopology`. This is documented, so it is not drift,
but it means the original “LangGraph strengths” half of the intent is only partly delivered. Do not
fake coverage: either implement one legitimate parallel shape when the live loop has one, or keep
the exact coverage table and state B is a hybrid.
